# Επανασχεδιασμός πακέτων: Τύποι πακέτων, Παροχές (Entitlements) και Οδηγός δημιουργίας (Wizard)

Ημερομηνία: 2026-10-12
Κατάσταση: Φάσεις Α (ADR-096) και Β (ADR-097) υλοποιήθηκαν. Η Φάση Γ εκκρεμεί (TD-049)· ανοιχτά σημεία της Β στο TD-053.
Σχετικά: ADR-040 (Package Entitlements and Allowance Ledger), ADR-062 (Entitlement Guidance), TD-017

> Γλώσσα: ελληνικά, με τους τεχνικούς όρους στα αγγλικά σε παρένθεση.

## 1. Σκοπός

Η φόρμα δημιουργίας πακέτου είναι σήμερα δύσχρηστη για μη τεχνικούς διαχειριστές:
- εκθέτει την εσωτερική μηχανή δικαιωμάτων (entitlements),
- έχει ένα πεδίο «Οικογένεια (Family)» που δεν επηρεάζει τίποτα,
- δεν καλύπτει τα εμπορικά μοντέλα που πουλάει πραγματικά ένα γυμναστήριο.

Η πρόταση έχει τρία σκέλη:
1. Ξαναστήνει την οντολογία σε δύο ανεξάρτητους άξονες: **Τύπος πακέτου** (πώς πωλείται) και **Τι περιλαμβάνει** (παροχές).
2. Ορίζει **presets ανά τύπο πακέτου**. Όλες οι τιμές είναι επεξεργάσιμες, **εκτός από όσες επιβάλλει ο τύπος** (κλειδωμένα πεδία, §6).
3. Σχεδιάζει έναν **οδηγό πολλών βημάτων (multi-step wizard)** με πεδία που αλλάζουν ανάλογα με τον τύπο (contextual fields) και ενότητα **Σύνθετες ρυθμίσεις (Advanced settings)** όπου ρυθμίζονται όλα.

Όλοι οι τύποι και όλες οι παροχές του καταλόγου υλοποιούνται σε όλα τα επίπεδα της εξαγωνικής αρχιτεκτονικής (hexagonal architecture). Ό,τι λείπει από το backend υλοποιείται πλήρως, όχι ως απλή ετικέτα.

Χρησιμοποιείται μόνο σε analytics και φίλτρα αναζήτησης. Αναμιγνύει *ποσότητα* και *υπηρεσία* και μπορεί να αντιφάσκει με τα όρια. | `finance/membership_package.ex`, `PackagesTab.tsx` |

**Τι υπάρχει ήδη στο backend:**
- τύποι μαθημάτων (`class_type`),
- κρατήσεις με χωρητικότητα,
- παρουσίες με no-show,
- βιβλίο κινήσεων παροχών (allowance ledger) με κρατήσεις/οριστικοποιήσεις (reservation saga),
- κωδικοί προσφοράς (promotion codes), referrals,
- ανάθεση προγράμματος, μηνύματα.

**Τι δεν υπάρχει καθόλου:**
- λίστα αναμονής (waitlist), παράθυρο κράτησης (booking window), πολιτική ακύρωσης (cancellation policy),
- καταστήματα (locations), ραντεβού PT (appointments), αξιολογήσεις (assessments),
- πάγωμα (freeze), επισκέπτες (guests), check-in χώρου,
- εκδηλώσεις (events), διατροφικά πλάνα (nutrition), βίντεο (on-demand), form review, SLA απόκρισης,
- πρόσθετα (add-ons), κοινόχρηστες συνδρομές (shared), εταιρικοί πληρωτές (corporate payers).

## 3. Δύο επίπεδα «πώλησης»

1. **Πλατφόρμα → γυμναστήριο (SaaS plan):** ποιες λειτουργίες έχει ο οργανισμός. Είναι ξεχωριστή οντολογία (feature flags ανά οργανισμό) και **εκτός** αυτού του εγγράφου.
2. **Γυμναστήριο → μέλος:** τι περιλαμβάνει ένα πακέτο. Αυτό είναι το αντικείμενο του εγγράφου.

Ανάμεσά τους προτείνεται η ρύθμιση **«Ενότητες (Modules)»** ανά γυμναστήριο. Το γυμναστήριο ανάβει μόνο ό,τι χρησιμοποιεί (π.χ. PT, Online καθοδήγηση, Ελεύθερη πρόσβαση). Ό,τι είναι σβηστό **δεν εμφανίζεται ποτέ** στον οδηγό πακέτων: ούτε ο τύπος, ούτε οι παροχές του. Αργότερα το SaaS plan απλώς θα περιορίζει ποιες ενότητες επιτρέπεται να ανάψει. Είναι το πιο αποτελεσματικό εργαλείο αποσυμφόρησης (declutter).

## 4. Οντολογία

### 4.1 Άξονας 1: Τύπος πακέτου (Package type), δηλαδή πώς πωλείται

Αντικαθιστά την «Οικογένεια (Family)».

| Τύπος | Παράδειγμα | Ορισμός τύπου (definition) |
|---|---|---|
| **Συνδρομή (Membership)** | Μηνιαία / τριμηνιαία / ετήσια | Επαναλαμβανόμενη χρέωση ανά περίοδο |
| **Πακέτο επισκέψεων (Class pack)** | 10 επισκέψεις, λήγουν σε 3 μήνες | Εφάπαξ αγορά, Ν μονάδες, ημερομηνία λήξης |
| **Μεμονωμένη επίσκεψη (Drop-in)** | 1 μάθημα 12 € | Εφάπαξ αγορά, μία μονάδα |
| **Δοκιμαστικό (Trial)** | 1 εβδομάδα δωρεάν | Περιορισμένη διάρκεια, κανόνας επιλεξιμότητας (eligibility) |
| **Πακέτο PT (PT session pack)** | 10 συνεδρίες PT | Εφάπαξ αγορά, Ν ατομικές/ημι-ατομικές συνεδρίες |
| **Πρόσθετο (Add-on)** | + Διατροφικό πλάνο 20 €/μήνα | Αγοράζεται μόνο πάνω σε βασικό πακέτο |
| **Κοινόχρηστη (Shared)** | Ζευγάρι, γονιός + παιδί | Ένας πληρωτής, πολλοί δικαιούχοι (beneficiaries) |
| **Εταιρική (Corporate)** | Η εταιρεία πληρώνει για Ν θέσεις | Τρίτος πληρωτής (third-party payer), θέσεις (seats) |

### 4.2 Άξονας 2: Τι περιλαμβάνει (What's included), δηλαδή ο κατάλογος παροχών (Entitlement catalog v2)

Είδη (kinds): **Access** (ναι/όχι), **Quota** (μετρούμενες μονάδες: όριο, περίοδος μηδενισμού, μεταφορά υπολοίπου/rollover), **Modifier** (αλλάζει κανόνα: ημέρες, ώρες, %), **Scope** (εύρος: τύποι μαθημάτων, καταστήματα, ώρες), **Informational** (εμφανίζεται μόνο, δεν ελέγχεται).

| Κατηγορία | Παροχή | Είδος | Επιβάλλεται από (bounded context) |
|---|---|---|---|
| **Ομαδικά μαθήματα** | Πρόσβαση | Access | Scheduling |
| | Επισκέψεις | Quota | Finance ledger |
| | Τύποι μαθημάτων | Scope | Scheduling |
| | Όρια ανά τύπο μαθήματος | Quota ανά scope | Finance ledger |
| | Χρέωση μονάδων (credit weighting): ιδιότητα του **τύπου μαθήματος** | Quota modifier | Scheduling → Finance |
| | Χρονικά παράθυρα (off-peak) | Scope | Scheduling |
| **Προνόμια κράτησης** | Παράθυρο κράτησης | Modifier (ημέρες) | Scheduling |
| | Προτεραιότητα λίστας αναμονής | Modifier | Scheduling |
| | Όριο ακύρωσης | Modifier (ώρες) | Scheduling |
| | Απαλλαγή από ποινή μη εμφάνισης | Modifier | Scheduling + Finance |
| **Προσωπική προπόνηση** | Συνεδρίες 1:1 / ημι-ατομικές | Quota + μορφή | Appointments (νέο) |
| | Αξιολογήσεις | Quota | Appointments + Wellbeing |
| **Απομακρυσμένη καθοδήγηση** | Ανατεθειμένο πρόγραμμα | Access + Quota | Workouts |
| | Μηνύματα με coach / check-ins | Access + Quota | Messaging |
| | Ανασκόπηση βίντεο τεχνικής (form review) | Quota | Coaching |
| | Χρόνος απόκρισης (response SLA) | Modifier (ώρες) | Messaging / Coaching |
| | Διατροφικό πλάνο | Access | Nutrition (νέο) |
| **Ψηφιακό περιεχόμενο** | Βιβλιοθήκη προπονήσεων | Access | Workouts / Execution |
| | Βίντεο κατ' απαίτηση (on-demand) | Access | Content (νέο) |
| | Προχωρημένα στατιστικά | Access | Analytics |
| **Πρόσβαση στον χώρο** | Ελεύθερη χρήση (open gym) | Access + Quota | Facility check-in (νέο) |
| | Καταστήματα (locations) | Scope | Organizations + Scheduling |
| | Παροχές χώρου (σάουνα, locker, πετσέτα…) | Informational | — |
| **Εμπορικά προνόμια** | Προσκλήσεις φίλων (guest passes) | Quota | Scheduling + Identity |
| | Ημέρες πάγωσης (freeze days) | Quota ανά έτος | Finance (membership lifecycle) |

Τα κανάλια × δυνατότητες (channels × capabilities) γίνονται **εσωτερική λεπτομέρεια** του backend. Κάθε παροχή του καταλόγου αντιστοιχίζεται στο σωστό ζεύγος, και ο admin δεν τα βλέπει ποτέ.

### 4.3 Εμπορικοί όροι (Commercial terms) ανά πακέτο

Δεν είναι παροχές προς το μέλος, αλλά όροι πώλησης. Ζουν στο πακέτο:
- τιμή, νόμισμα
- περίοδος χρέωσης, αυτόματη ανανέωση (auto-renew)
- ελάχιστη δέσμευση (minimum commitment)
- τέλος εγγραφής (joining fee)
- ισχύς (validity) και έναρξη ισχύος: από την αγορά ή από την πρώτη χρήση
- επιλεξιμότητα (eligibility)
- συμβατά βασικά πακέτα (για Add-on)
- δικαιούχοι (για Shared)
- θέσεις και πληρωτής (για Corporate)

## 5. Presets ανά τύπο πακέτου

**Κανόνας:** Κάθε τύπος έχει πλήρες preset, δηλαδή τιμή για **κάθε** πεδίο του καταλόγου. Ο admin μπορεί να αλλάξει κάθε τιμή, **εκτός από όσες επιβάλλει ο τύπος**. Αυτές σημειώνονται με 🔒 και περιγράφονται αναλυτικά στην §6. Οι τιμές «όπως το γυμναστήριο» παραπέμπουν στις γενικές ρυθμίσεις του οργανισμού και ακολουθούν τις αλλαγές τους, μέχρι ο admin να ορίσει συγκεκριμένη τιμή.

## 6. Κλειδωμένα πεδία (Type-enforced fields)

### 6.1 Τι σημαίνει «κλειδωμένο»

Ένα πεδίο είναι **κλειδωμένο** όταν η τιμή του είναι μέρος του **ορισμού του τύπου**. Αν άλλαζε, το πακέτο θα ήταν άλλος τύπος ή θα έπαυε να έχει νόημα. Παραδείγματα:
- Ένα Drop-in με 5 επισκέψεις είναι Πακέτο επισκέψεων.
- Ένα Πακέτο επισκέψεων με αυτόματη ανανέωση είναι Συνδρομή.
- Ένα Add-on χωρίς βασικό πακέτο δεν μπορεί να υπάρξει.

**Γενικός κανόνας:** κλειδώνεται **η τιμή που ορίζει τον τύπο**, όχι η ποσότητα. Για παράδειγμα, στο Πακέτο επισκέψεων είναι κλειδωμένο ότι οι επισκέψεις *έχουν όριο*, αλλά ο *αριθμός* (10) αλλάζει ελεύθερα.

### 6.3 Πώς εμφανίζονται στο UI

- **Στα βήματα του οδηγού**, τα κλειδωμένα πεδία **δεν εμφανίζονται ως πεδία**, για να μη γεμίζει η οθόνη. Στην κορυφή του βήματος εμφανίζεται μια διακριτική γραμμή «🔒 Ορίζεται από τον τύπο: εφάπαξ πληρωμή · χωρίς ανανέωση · 1 επίσκεψη» με σύνδεσμο «Τι σημαίνει;».
- **Στις Σύνθετες ρυθμίσεις**, εμφανίζονται στη θέση τους ως **πεδία μόνο για ανάγνωση (read-only)** με εικονίδιο 🔒 και βοηθητικό κείμενο: «Ορίζεται από τον τύπο *Drop-in*. Για πολλές επισκέψεις, χρησιμοποίησε *Πακέτο επισκέψεων*.» Το τελευταίο είναι σύνδεσμος που αλλάζει τύπο (§6.4).
- **Προσβασιμότητα:** χρησιμοποιείται `readonly` και όχι `disabled`, ώστε οι αναγνώστες οθόνης να διαβάζουν την τιμή. Η αιτία συνδέεται με `aria-describedby`.
- **Έλεγχος (Review):** ξεχωριστή, συμπτυγμένη ενότητα «Ορίζεται από τον τύπο», χωρίς σύνδεσμο «Αλλαγή».
- Τα κλειδωμένα πεδία **δεν** παίρνουν ποτέ σήμανση «Αλλαγμένο» και **δεν** επηρεάζονται από την «Επαναφορά προτεινόμενων τιμών».

### 6.4 Αλλαγή τύπου κατά τη δημιουργία

- Γίνεται από το βήμα 1 ή από τον σύνδεσμο ενός κλειδωμένου πεδίου.
- Ο οδηγός **κρατά** όσα ταιριάζουν και στον νέο τύπο: όνομα, περιγραφή, τιμή, επεξεργάσιμες παροχές που υπάρχουν και στους δύο τύπους.
- Εφαρμόζει τα presets και τα κλειδώματα του νέου τύπου στα υπόλοιπα.
- Πριν την αλλαγή εμφανίζει σύνοψη: «Θα αλλάξουν: ανανέωση → όχι, επισκέψεις → 10 με όριο. [Αλλαγή τύπου] [Ακύρωση]».

### 6.5 Επιβολή στο backend

Τα κλειδώματα **δεν** είναι μόνο UI. Είναι **αμετάβλητοι κανόνες (invariants)** του domain:
- Ένα pure module `PackageTypePolicy` ορίζει για κάθε τύπο τα κλειδωμένα πεδία και τις τιμές τους, μαζί με τους κανόνες «τουλάχιστον ένα» (Drop-in, Add-on).
- Το API απορρίπτει παραβίαση με σταθερό κωδικό σφάλματος `package_type_invariant_violated` και παραμέτρους `field` και `package_type`. Ο κωδικός μεταφράζεται στο frontend όπως οι υπόλοιποι (ADR-062).
- Το endpoint presets (`GET /packages/presets?type=…`) επιστρέφει για κάθε πεδίο `value`, `locked` και `locked_reason` (κλειδί μετάφρασης). Έτσι το frontend δεν έχει δική του λίστα κλειδωμάτων, και υπάρχει μία πηγή αλήθειας.

## 7. UX: Οδηγός δημιουργίας πακέτου (Package creation wizard)

### 7.1 Αρχές σχεδιασμού (με βάση καθιερωμένες πρακτικές)

1. **Οδηγός για τη δημιουργία, μία σελίδα για την επεξεργασία.** Οι wizards ταιριάζουν σε σπάνιες διαδικασίες και αρχάριους χρήστες. Για επαναλαμβανόμενη χρήση χρειάζεται γρηγορότερος δρόμος. Γι' αυτό η **επεξεργασία** είναι μία σελίδα με ενότητες, και υπάρχει **«Αντιγραφή πακέτου (Duplicate)»** που ανοίγει τον οδηγό προσυμπληρωμένο. [NN/g: Wizards]
2. **Εμφάνιση μόνο των σχετικών βημάτων.** Τα βήματα και τα πεδία εξαρτώνται από τον τύπο. [NN/g: Wizards]
3. **Δείκτης προόδου (progress indicator) με περιγραφικούς τίτλους βημάτων.** Το τρέχον βήμα επισημαίνεται και τα ολοκληρωμένα σημειώνονται με ✓. Τα κουμπιά λένε πού οδηγούν, π.χ. «Συνέχεια: Τι περιλαμβάνει», όχι σκέτο «Επόμενο». Υπάρχει ρητό κουμπί «Πίσω». [NN/g: Wizards]
4. **Αποθήκευση προχείρου (draft).** Ο admin μπορεί να βγει και να συνεχίσει αργότερα. [NN/g: Wizards]
5. **Μία στήλη (single column).** Οι φόρμες δύο στηλών προκαλούν σύγχυση για τη σχέση των πεδίων. [Baymard]
6. **Ετικέτα πάνω από το πεδίο, βοηθητικό κείμενο κάτω.** Το placeholder δεν αντικαθιστά ποτέ την ετικέτα. [Baymard / uxdesign.cc]
7. **Έξυπνες προεπιλογές (smart defaults) με βάση το πλαίσιο.** Οι στατικές προεπιλογές αποφεύγονται. Οι προεπιλογές που βγαίνουν από ό,τι ήδη ξέρουμε (εδώ, ο τύπος πακέτου) είναι ο ενδεδειγμένος τρόπος. [Baymard / uxdesign.cc]
8. **Σταδιακή αποκάλυψη (progressive disclosure).** Τα δευτερεύοντα πεδία μένουν στις «Σύνθετες ρυθμίσεις». [NN/g: Progressive Disclosure]
9. **Έλεγχος στο τέλος (Review / check answers)** με σύνδεσμο «Αλλαγή» σε κάθε ενότητα. [GOV.UK Design System: Check answers]
10. **Επικύρωση κατά την έξοδο από το πεδίο (inline validation on blur).** Τα μηνύματα είναι σε απλή γλώσσα και λένε τι να γίνει. [Baymard]
11. **Απλή γλώσσα και μονάδες στο πεδίο.** Το επίθημα δείχνει τη μονάδα, π.χ. «€ / μήνα», «ημέρες», «επισκέψεις».
12. **Προσβασιμότητα και κινητά.** `fieldset`/`legend` για ομάδες, η εστίαση πάει στον τίτλο του νέου βήματος, η σύνοψη ανακοινώνεται με `aria-live`. Κουμπιά ≥ 44 px, σταθερή μπάρα κουμπιών στο κάτω μέρος (sticky footer) στα κινητά.

### 7.6 Σύνθετες ρυθμίσεις (Advanced settings)

- **Μορφή:** Πλαϊνό συρτάρι (drawer). Στα κινητά γίνεται πλήρης οθόνη. Περιέχει **πεδίο αναζήτησης ρυθμίσεων** στην κορυφή και ενότητες-ακορντεόν (accordion) με σειρά σχετικότητας για τον τύπο. Οι ενότητες που δεν αφορούν τον τύπο είναι στο τέλος, κλειστές.
- **Περιεχόμενο:** **Όλα** τα πεδία του καταλόγου (§4.2) και των εμπορικών όρων (§4.3), συμπληρωμένα από το preset. Τα κλειδωμένα πεδία εμφανίζονται στη θέση τους ως read-only με 🔒, την αιτία και σύνδεσμο προς τον κατάλληλο τύπο (§6.3).
- **Κάθε πεδίο:** ετικέτα, στοιχείο, βοηθητικό κείμενο, και «Αλλαγμένο ↺» όταν διαφέρει από το preset. Στην κορυφή υπάρχει «Επαναφορά όλων στις προτεινόμενες τιμές».

| Ενότητα | Πεδία και στοιχεία UI |
|---|---|
| **Χρέωση & όροι** | Αυτόματη ανανέωση (toggle)· Ελάχιστη δέσμευση (dropdown: καμία / 3 / 6 / 12 μήνες)· Τέλος εγγραφής (€)· Έναρξη ισχύος (radio: αγορά / πρώτη χρήση)· Στοίβαξη (toggle, για εφάπαξ πακέτα)· Υπενθύμιση λήξης (dropdown ημερών) |
| **Ομαδικά μαθήματα** | Επισκέψεις (όπως βήμα 3)· Μεταφορά υπολοίπου (rollover: toggle + μέγιστο)· Τύποι μαθημάτων (multi-combobox)· Όρια ανά τύπο (επαναλαμβανόμενη γραμμή: τύπος + όριο + περίοδος, «+ Προσθήκη ορίου»)· Χρονικά παράθυρα (ημέρες εβδομάδας ως chips + ώρα από/έως) |

| **Ψηφιακό περιεχόμενο** | Βιβλιοθήκη (toggle)· Βίντεο on-demand (toggle)· Προχωρημένα στατιστικά (toggle) |
| **Χώρος** | Open gym (toggle + όριο/περίοδο)· Καταστήματα (multi-combobox, «Όλα»)· Παροχές χώρου (chips: Σάουνα, Ντουλαπάκι, Πετσέτα, Πάρκινγκ, Παιδότοπος + «Άλλο» ελεύθερο κείμενο) |

| **Οργάνωση** | Ετικέτες (tags: combobox με δημιουργία νέων)· Ενεργό (toggle) |

### 7.7 Βήμα Έλεγχος & δημιουργία (Review)

- Μεγάλη **κάρτα «Τι βλέπει το μέλος»**, όπως θα εμφανιστεί στο μέλος.
- Λίστα περίληψης ανά ενότητα (Τύπος, Βασικά, Τι περιλαμβάνει, ειδικά βήματα, Σύνθετες), με σύνδεσμο **«Αλλαγή»** δεξιά σε κάθε ενότητα.
- Συμπτυγμένη ενότητα **«Ορίζεται από τον τύπο»** με τα κλειδωμένα πεδία, χωρίς σύνδεσμο «Αλλαγή».
- Ξεχωριστή σημείωση **«Αλλαγές από τις προτεινόμενες τιμές: 3»**, που ανοίγει λίστα με όσα άλλαξαν.
- Προειδοποιήσεις, χωρίς να μπλοκάρουν: π.χ. «Το πακέτο δεν περιλαμβάνει καμία υπηρεσία που ελέγχει η εφαρμογή».
- Κουμπιά: **Πίσω** · **Αποθήκευση ως πρόχειρο** · **Δημιουργία πακέτου** (κύριο).

### 7.8 Επεξεργασία, αντιγραφή, πρόχειρα

- **Επεξεργασία:** μία σελίδα με τις ίδιες ενότητες (όχι wizard), ίδια πεδία, ίδια σήμανση «Αλλαγμένο» και ίδια κλειδώματα.
  - Μπάνερ: «Οι αλλαγές ισχύουν για νέες αγορές. Όσοι έχουν ήδη το πακέτο κρατούν τους όρους που αγόρασαν.» Αυτό ισχύει ήδη λόγω snapshot.
  - Αν υπάρχουν ενεργοί κάτοχοι και ο admin αλλάξει **τύπο**, προτείνεται «Δημιουργία αντιγράφου ως νέος τύπος», ώστε να μη σπάσει η αντιστοίχιση των υπαρχόντων.
- **Αντιγραφή (Duplicate):** ανοίγει τον οδηγό στο βήμα 2, με όλα προσυμπληρωμένα και όνομα «… (αντίγραφο)».
- **Πρόχειρα (drafts):** εμφανίζονται στη λίστα πακέτων με ένδειξη «Πρόχειρο». Δεν πωλούνται και δεν ανατίθενται.

## 8. Backend: υλοποίηση σε όλα τα επίπεδα

**Λίστα ελέγχου ανά λειτουργία (hexagonal checklist):**
1. **Domain:** pure policies και value objects, π.χ. `PackageType`, `PackageTypePolicy` (κλειδώματα/invariants, §6.5), `EntitlementCatalog`, `PresetResolver`, πολιτικές ανά παροχή.
2. **Application:** use cases και sagas με Finance (reserve → write → finalize/release).
3. **Ports:** behaviours ανά context.
4. **Adapters:** Ecto schemas, migrations, Oban workers, Meilisearch όπου χρειάζεται.
5. **API:** controllers, κλειστό OpenAPI contract, αναπαραγωγή των τύπων του frontend.
6. **Web:** admin (wizard, προφίλ μέλους) και μέλος (billing, κρατήσεις).
7. **i18n:** 12 γλώσσες + Gettext. **Notifications / realtime:** όπου αλλάζει κατάσταση.
8. **Tests:** domain, adapter με PostgreSQL, contract, frontend. **ADR** και ενημέρωση του `technical_debt.md`.

**Σημεία σχεδιασμού:**
- Το `package.type` αντικαθιστά το `family`. Τα snapshots, οι γραμμές τιμολογίων και τα analytics views μεταφέρονται με migration.
- Οι παροχές αποθηκεύονται ως **`entitlement_version: 2`** στο `params`: καθαρή αναπαράσταση του καταλόγου με τιμή για κάθε παροχή. Το v1 διαβάζεται και μετατρέπεται με συμβατότητα προς τα πίσω.
- Τα **presets** και τα **κλειδώματα** ζουν στο domain του backend, ώστε το frontend απλώς να τα ζητά (`GET /packages/presets?type=…`, με `value`, `locked`, `locked_reason` ανά πεδίο). Έτσι υπάρχει μία πηγή αλήθειας και το API επικυρώνει τα ίδια πράγματα.
- **Κωδικός πακέτου:** παράγεται στο backend από το όνομα, με μεταγραφή ελληνικών (ΕΛΟΤ 743) και επίθημα σε σύγκρουση (`_2`). Είναι αμετάβλητος μετά τη δημιουργία.
- Διορθώνεται το σφάλμα του `receive_coaching_touchpoints` (§2).

## 9. Φάσεις υλοποίησης

Τρεις φάσεις. Κάθε φάση είναι πλήρης κάθετα (end-to-end) σε όλα τα επίπεδα και μπορεί να βγει μόνη της στην παραγωγή.

| Φάση | Περιεχόμενο |
|---|---|
| **Α. Θεμέλια & βασικοί εμπορικοί τύποι** | Package type (και οι 8 τύποι στο domain), κατάλογος v2, presets και κλειδώματα στο backend, μετάπτωση Family/v1, Ενότητες (Modules), νέος wizard και σελίδα επεξεργασίας, προβολή μέλους, αυτόματος κωδικός με μεταγραφή, διόρθωση bug coaching. **Λειτουργικοί τύποι:** Συνδρομή, Πακέτο επισκέψεων (στοίβαξη, λήξη), Drop-in, Trial (επιλεξιμότητα, μετατροπή). **Παροχές:** ομαδικά μαθήματα με εύρος και όρια ανά τύπο μαθήματος, ανατεθειμένο πρόγραμμα, μηνύματα/check-ins, αξιολογήσεις και open gym μόνο ως αποθηκευμένες τιμές μέχρι τη Φάση Β/Γ. |
| **Β. Κανόνες κρατήσεων, προνόμια & χώρος** | Παράθυρο κράτησης, ακύρωση, ποινή no-show, λίστα αναμονής + προτεραιότητα, off-peak, credit weighting, rollover, πάγωμα, guest passes, έκπτωση μέλους, εκδηλώσεις, καταστήματα, check-in open gym, παροχές χώρου |
| **Γ. Νέες υπηρεσίες & μοντέλα πληρωμής** | Ραντεβού (PT 1:1 / ημι-ατομικό, αξιολογήσεις, Πακέτο PT), form review, SLA, διατροφικό πλάνο, βιβλιοθήκη, on-demand, προχωρημένα στατιστικά, Add-on, Κοινόχρηστη, Εταιρική |

**Ο wizard** εμφανίζει σε κάθε φάση μόνο τους τύπους και τις παροχές που έχουν ήδη υλοποιηθεί. Ο admin δεν βλέπει ποτέ επιλογή που δεν λειτουργεί.

**Προσωρινές αποφάσεις για τη Φάση Α** (αλλάζουν αν αποφασίσεις διαφορετικά):
- Τα πακέτα επισκέψεων στοιβάζονται. Καταναλώνεται πρώτα όποιο λήγει νωρίτερα.
- Το Trial κλειδώνει «μία φορά ανά άτομο». Το «μόνο νέα μέλη» είναι ενεργό εξ ορισμού, αλλά επεξεργάσιμο.

## 10. Ανοιχτές αποφάσεις

1. **Πακέτα επισκέψεων:** στοίβαξη ναι/όχι· σειρά κατανάλωσης (προτείνεται: πρώτα όποιο λήγει νωρίτερα).
2. **Κοινόχρηστη:** όρια ανά άτομο ή κοινά (προεπιλογή)· ανήλικοι χωρίς λογαριασμό;
3. **Εταιρική:** τιμολόγηση με βάση τις συμφωνημένες ή τις χρησιμοποιημένες θέσεις;
4. **PT:** ο coach δηλώνει διαθεσιμότητα και το μέλος κλείνει μόνο του, ή κλείνει ο admin/coach;
5. **Open gym check-in:** QR στην υποδοχή / αυτο-check-in / καταγραφή από υπάλληλο;
6. **Πάγωμα:** μετάθεση λήξης, παύση χρέωσης, ή και τα δύο;
7. **Σειρά φάσεων:** επιβεβαίωση των τριών φάσεων της §9.
8. **Αλλαγή τύπου σε πακέτο με ενεργούς κατόχους:** μόνο μέσω αντιγράφου (πρόταση §7.8) ή επιτρέπεται;
9. **Drop-in ως ημερήσια πρόσβαση (day pass):** να επιτρέπεται η μία μονάδα να είναι open gym αντί για μάθημα (πρόταση §5.2 ¹);
10. **Κλειδώματα:** επιβεβαίωση της λίστας της §6.2, ιδίως ότι το Trial κλειδώνει «μία φορά ανά άτομο» ενώ το «μόνο νέα μέλη» μένει επεξεργάσιμο.
