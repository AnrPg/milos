## Rules for every workstream

- **Hexagonal layers** (ADR-043 and the `lib/palee/fiscal/**` reference style): ports in the domain, adapters chosen via config, one application service per controller, an injected clock, Req with `req_options` from config, and an outbox for anything external.
- **External providers** (SMS, Viber, WhatsApp, Google, watch platforms, door controllers, LLMs) sit behind a port. Each port gets a **sandbox adapter** used in dev and test and a real adapter. Each box uses its own credentials where the provider bills the box. Credentials are encrypted, never returned by the API, never logged.
- **UI only after ANR approves clickable mockups with 2–3 alternatives** (standing rule since 2026-10-29). Every workstream first builds the domain, API and tests, and writes its mockup section; screens come after ANR's pick.
- **Names** follow `docs/product/ontology.md` (EN + EL); new terms are added there. Keep the calm default; rare options go under «Προχωρημένα» (ADR-255).
- **Tests:** every change updates its tests (domain, integration under RLS, controller, web unit; Playwright once screens exist).
- **GDPR:** consent before any tracking (C5), and opt-in for marketing channels (C3, C2). Data minimisation for AI features (F4, G3, C8): the box's own data only, under its RLS context.
